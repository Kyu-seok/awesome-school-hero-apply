# 신청을 기관(B2B) 단위 요청으로 모델링한다

과제 문구("교육 신청")만 보면 학생이나 보호자가 기수에 등록하는 B2C 흐름으로도 읽힌다. 하지만 실제 히어로스쿨(hero-school.net)을 조사해 보면, 학교·기관 담당자가 교육과 수업 희망일을 골라 문의하고, 담당자가 연락해 일정을 확정하는 B2B 흐름이다(이 저장소의 데모 서비스는 챔피언스쿨이라는 이름을 쓰며, 실제 히어로스쿨과는 별개다). 그래서 신청은 기관을 대표하는 성인 신청자가 하나의 교육과 수업 희망일에 대해 접수하는 요청으로 모델링하고, 기수(Cohort) 개념은 두지 않는다.

## Considered Options

- **보호자가 학생을 대신해 기수에 신청 (B2C)**: 과제 문구와는 맞지만 실제 서비스 흐름과 다르다. 만 14세 미만 아동 정보 때문에 법정대리인 동의도 다뤄야 한다.
- **기관이 교육의 수업 희망일에 신청 (B2B, 채택)**: 실제 운영 흐름과 같다. "수업 희망일은 최소 3주 뒤" 같은 실제 FAQ 규칙을 도메인 규칙으로 옮길 수 있다.

## Consequences

- 정원과 모집 기간은 다루지 않는다. 학교마다 수업이 따로 잡히기 때문이다.
- "연락 가능 날짜 기준 자동 안내 메일"은 운영자가 전화하기 전에 메일로 먼저 연락을 열어 주는 자동화로 해석한다.
